# 功能清单（Function Tree）— harness-cardbattle（卡牌对战：Godot 4.7 + GDScript）

> **全体系唯一锚点。** 需求、流程、设计、测试都引用这里的 ID。
> 不在这里的 ID 是悬空引用，L5 门会拦。**改功能，先改这份表。**

## 编号规则

| 层级 | 名称 | 格式 | 含义 |
|---|---|---|---|
| 一级 | 功能模块 | `M01` | 业务域边界 |
| 二级 | 功能 | `M01.F01` | 一个完整业务步骤 / 独立闭环 |
| 三级 | 功能子项 | `M0x.F0y.I0z` | 技术交付单元，对应一个页面区块或核心逻辑模块 |

**硬规则**

1. 编号单调递增，永不复用。废弃改状态，不删行。
2. 子项编号必须以父级为前缀。
3. 拆不出子项的功能 → 它其实是子项，往上并。

**状态**：`规划` | `开发中` | `已上线` | `已废弃`
**子项类型**：`页面` | `标签页` | `查询` | `按钮` | `报表` | `接口`
